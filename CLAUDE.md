# Kaboom Arena (PWA)

Vanilla JS + Canvas in `public/game/` (no build step). A Rails 8 API app only relays online rooms (`app/channels/room_channel.rb`).

## Run and test
- `bin/rails s -b 0.0.0.0` -> http://localhost:3117 (on a phone: use the LAN IP). Solo/local only need a static server on `public/`.
- Tests (no dependencies): `cd public/game && node --test sim.test.mjs ai.test.mjs netcode.test.mjs modes.test.mjs lobby.test.mjs settings.test.mjs haptics.test.mjs campaign.test.mjs fx.test.mjs director.test.mjs extras.test.mjs raycast.test.mjs fpsinput.test.mjs nav.test.mjs sound.test.mjs music.test.mjs dlss6.test.mjs determinism.test.mjs specials.test.mjs replay.test.mjs daily.test.mjs sharecard.test.mjs emote.test.mjs`.
- UI and code are in English, no i18n.

## Architecture
- `sim.js` is the only game logic: pure, deterministic, fixed 60 Hz. Solo/local: the browser simulates. Online: the host's browser simulates and broadcasts snapshots (30 Hz); guests only send inputs.
- `input.js`: one "source" per device (kb1 WASD/ZQSD + Space, kb2 arrows + Enter, touch, padN). Solo/online merge all sources; local mode gives one source per player, claimed by pressing its bomb key.
- Graphics are 100% drawn in code (`render.js`), no third-party game assets.
- Optional 3D renderer (`render3d.js`, Three.js r170 vendored in `public/game/vendor`, import map in `index.html`): same game state as the 2D one, loaded on demand. Modes: Classic (2D) / 3D / DLSS 5 (parody: bloom, chromatic aberration, "Neural Faces", dynamic resolution). Every vendored file must be added to `FILES` in `public/sw.js`.
- `input.js` ignores the game keys when a button outside `#game` has focus, so menu buttons stay keyboard-operable; `main.js` wraps `draw` in try/catch so one bad frame never stops the render loop.
- Home screen background is a live bot match (`home.js`), throttled on purpose (CPU is a first-class constraint).
- `cable.yml` uses the `async` adapter: a single Puma process only (never `WEB_CONCURRENCY` > 1), otherwise switch to Solid Cable or Redis.
- Setting `offline` (store group): asks the service worker (`{t:"precache"}` message, reply `precached`) to cache every missing file in `FILES`, lazy ones included. `ux.js` `watchUpdates` calls `reg.update()` at load and on tab focus; with `offline` on, a new worker precaches itself once active and the update toast only shows after that, so one Reload is enough.
- `public/sw.js`: hand-written precache list, add every new file to it and bump the cache name. It is network-first (cache is for offline only): stale-while-revalidate served a mix of old and new ES modules and broke inputs.

## Match settings and themes
- `settings.js` (pure, tested in `settings.test.mjs`) holds the match options: bot level, rounds to win, arena layout, theme, power-ups, sudden death, teams, friendly fire. They persist in localStorage (`settings`), apply to solo, local and the online host, and `roundOpts` builds the `newGame` options for every round. Teams are `[0,1,0,1]` and only exist with exactly 4 players.
- Themes are purely visual and live in `look.js` for both renderers (2D palette + a `d3` block for 3D). The host sets `s.cfg.theme` after `newGame`; unknown themes fall back to grass. A new theme needs both blocks.
- `cfg` (theme, teams, layout...) only travels with grid snapshots, so a guest always has it when it first renders. The snapshot wrapper also carries `w` (rounds to win).

## Accessibility, feedback and UX modules
- `look.js` also holds the player palette (standard and colour-blind, Okabe-Ito) and team colours: `palette()` and `teamInfo()` read `view.cb`, which `main.js` sets from `settings.cb`. Any new colour consumer must go through them, no local tables. Colour-blind mode also shows a 1-4 tag above heads and digits in HUD chips.
- `haptics.js` is pure and injectable (tests in `haptics.test.mjs`): phone `navigator.vibrate` and gamepad rumble (`vibrationActuator.playEffect("dual-rumble")`, legacy `hapticActuators` fallback), throttled, gated by the `vibrate`/`rumble`/`intensity` settings. `observe(mem, state)` derives events from successive game states so it works the same for solo, host and guest; in local mode rumble goes to the affected player's pad only.
- `settings.js` also holds `cb`, `reduce` (auto/on/off, see `reduced()`), `vibrate`, `rumble`, `intensity`; fields flagged `a11y: true` render in the "Accessibility & feedback" group. Reduce motion stops 3D camera shake and sparks (`r3.setStill`) and the home attract loop (`home.js` `setStill`); it adds no timers.
- `ux.js`: tutorial overlay (`helpSeen` flag), `beforeinstallprompt` capture plus an iOS "Add to Home Screen" hint, and the "New version available" toast (relies on the service worker's `skipWaiting`/`clients.claim`, so Reload is just `location.reload()`).

## Story mode
- `campaign.js` (pure: roster, `RELATIONS`/`KINDS`, per-fighter `ladder`, `fightOf`, persistence with an injected storage), `story.js` (all text, relation templates, `banter(a, b)`), `storyui.js` (DOM screens: select, intro, VS, win, continue, ending, unlock) and `campaign.test.mjs`. `mode === "story"` reuses the solo flow with fixed rules (first to 2 rounds, sudden death, power-ups, friendly fire on); bot level and stage (layout/theme) come from the ladder; the boss fight uses a packed arena (`softDensity` 0.9). Progress lives in localStorage `story`.
- A new fighter needs a `ROSTER` entry, a ladder, a `TEXT` entry, a portrait in `public/portraits/` and an `sw.js` entry; every relation role used in `KINDS` needs a `TEMPLATES` entry in `story.js` (the test enforces it). `look.js` `setSuits(cols)` overrides suit colours by player index for story fights; `toMenu()` resets it and colour-blind mode keeps priority.
- Browser Back: `nav.js` (tested in `nav.test.mjs`) mirrors the open layers (a non-menu screen, the help overlay) in the history and reconciles them in a microtask, so Back closes the top layer instead of leaving the site: settings/lobbies go to the menu, a running offline game pauses first and then quits, online games ignore Back (use the ✕). `main.js` `show()` opens/closes the "screen" layer and `goBack()` decides what Back means; `ux.js` `initHelp` takes the same layer callbacks.
- Development serves `public/` with `Cache-Control: no-cache`: a long max-age mixed old and new ES modules ("does not provide an export named ..."). The service worker revalidates network-first requests with `cache: "no-cache"` for the same reason.
- UI font: one pixel font (Press Start 2P) for buttons, labels and titles (CSS block at the end of `index.html`); paragraphs keep the system font.
- UI rule: static screens, timers only while text types and during the continue countdown, no CSS animations. The pixel font (Press Start 2P, OFL, vendored) is only used on `#story`, story round banners and `#storyBtn`. Story navigation uses its own keydown handler and the pad callbacks in `main.js`.
- Dev flags: `?story=fast` kills the bot at the start of each round and `?story=lose` kills the human (used to fast-forward a run in tests and screenshots).

## Story co-op, choices and secret endings
- Local 2-player co-op: `campaign.js` `fightOf(id, i, run)` builds players hero, Sparky (the sidekick), foe, foe's partner; teams `[0,0,1]` or `[0,0,1,1]`; humans are ids 0 and 1 so `multi()` in `main.js` reuses the local-mode paths; `storyui.claim(name)` runs first in the bomb-press callback (the claim screen sets no focus: a focused button outside `#game` blocks key input). Fights 1-2 are 2v1, 3-7 are 2v2 (deterministic partner bot), the boss is 2v1; level floor "normal". Online co-op is out of scope. Story bubbles are off in co-op (`director.js` supports players 0 and 1 only).
- Choices: `CHOICES` in `campaign.js` (shown before fight `at`, effects apply to that fight only, kind/greed counters hidden) with texts in `story.js` `CHOICE_TEXT` (a test enforces both). Secret endings: `SECRET` conditions + `endingsOf`, texts in `ENDING_TEXT`, art in `ART_OF` (`storyui.js`) built from rectangles in `storyart.js`; the Story log lists them ("???" until found).
- Save v2 is backward compatible (all new fields optional: `co`, `ff`, `coop`, `ends`, `run.{co,ff,p,ct,lr}`); sanitising drops bad picks. `replay.js` `cleanOpts` accepts the three team layouts; `st` may carry `co`/`al`. Dev flag: `?story=fast&pick=N` auto-answers every choice.

## 3D effects (`fx.js`, `render3d.js`)
- `fx.js` is a pure, allocation-free observer (tests in `fx.test.mjs`): it diffs successive states and reports `reset`, `die`, `bomb`, `wall` and `pick`, so solo, host and guest animate the same way. The renderer derives death spins and ghosts, bomb drop/squash, wall crumble, item pops and the round-end hop from those events, and resets on a new round.
- Everything extra is gated by `setStill` (reduce motion) and uses no timers; DLSS parody gags (toasts, "hallucinated" brick, re-render shimmer, stat line) are tuned with the `GAG` constants and run on accumulated game time, so pauses and hidden tabs do not advance them. The `MOBILE` flag halves pools and sparks.
- Per-player `castShadow` is a whitelist (torso, head, legs, shoes, hands): do not re-add a `traverse`.

## DLSS 6 parody mode (`dlss6.js`, `dlss6ui.js`)
- The internal gfx value stays `"dlss"`. `dlss6.js` is pure (panel fields, sanitize, fake numbers, toast texts, boot stages, `createCadence` gag spacing >= 6 s on game time, quality governor, flare math); `dlss6ui.js` is the DOM splash and fake control panel (injects and removes its own `<style>`). Panel options persist in localStorage `dlss6`, the splash flag in sessionStorage `dlss6splash` (shown once per session, only on a user click, never online). `G` or the gear button opens the panel (back layer `"dlss"`, Esc closes; offline it pauses), `T` toggles the mode. Disclaimer text: "Parody. Not affiliated with NVIDIA." (splash, panel footer, tooltips, help). No brand colours: violet and blue only.
- `render3d.js`: desktop-only extras (mirrored block reflections, contact shadows, light shafts, lens flares) are built in `buildHeavy` via `syncHeavy` (desktop, DLSS, not reduced) and freed in `disposeHeavy`. Governor levels 3 = all, 2 = no shafts, 1 = no reflections/shadows, 0 = none; resolution only drops once effects are at 0. Traps: mirror meshes share `instanceMatrix` with the real blocks (never `dispose()` them); set the ground `renderOrder` only while it is transparent. Debug: `?dlss6=max` pins quality.

## Game feel (`director.js`)
- `director.js` is a pure, allocation-free observer plus orchestrator in the style of `fx.js` (tests in `director.test.mjs`): a state-diff tracker (kills, own-bomb deaths, chains, close calls; flames carry no owner so each blast is recomputed from the previous grid), the announcer queue (max 2, cooldowns, priorities), hit-stop/slow-mo timing, story speech-bubble placement and the round/match recap data. Its state lives at module scope in `main.js` because guests rebuild `game` on every snapshot; renderers read `g.call`, `g.bub`, `g.clock` and `g.ts`.
- Time effects (hit-stop 80 ms, 0.35x slow-mo for the deciding kill) scale the local accumulator and run only in solo, local and story: never in host or guest, so determinism and tick rates are untouched (online only gets visual punches). Reduce motion or the Slow-mo setting turns them off; the announcer then shows a static fade.
- Settings flagged `feel: true` render in the "Game feel" group (`#feelList`): Announcer, Slow-mo, Round recap. In-fight story lines live in `story.js` `fightLine(id, ev)`.
- Known limit: chain-reaction order is not replayed, so kill credit can be off by one in rare chains; a sliding bomb that explodes is not attributed.

## Extras in the sim (tiles, chaos, modes), opt-in via `newGame` opts
- `tiles: "few" | "many"` adds `state.floor` (W*H codes: `ICE=1`, `CONV=2..5` = `CONV + dir`, `SPIKE=6`, `TELE=10+k` for pair k); spike phase is a pure function of `tick` (`spikeIn(s, i)`: 0 = deadly, 1..45 = telegraph, cycle 165 ticks). Ice momentum (`p.vx/vy`), conveyor drift and the frenzy speed boost live inside `movePlayer` so guest prediction stays exact; teleports (20 ticks armed), spike kills and conveyors moving bombs/items are host-only in `step`.
- `chaos: true` schedules seeded events (`bombrain`, `itemrain`, `frenzy`, `quake`, `swap`) in `state.event = {type, t, ...}` with a 90-tick telegraph (`t` counts down; `tiles` or `a`/`b` show the targets; frenzy uses `on`).
- `mode: "hill" | "potato" | "survival"` (forces sudden death off): `state.hill` (3x3 zone, relocation telegraph in `next`, goal 30 points or highest at 90 s), `state.potato` (`holder`, 10 s fuse, passes by touch with a global cooldown, owner -1 blast of range 3), `state.survival` (humans then 12 dormant enemy slots `dormant: true` on team 1, waves activate `1 + wave` enemies, cap 8 alive, round ends when every human is dead). Renderers/HUD must skip `p.dormant` and non-alive enemy slots; the main loop must call `think` for every player id.
- Bots treat spikes as timed danger, never enter teleporters, avoid ice/conveyors in strict escape planning, flee bomb-rain bombs, head for the hill, chase or flee the potato holder, and hunt humans in survival. `extras.test.mjs` covers all of it, including prediction parity through ice, conveyors and frenzy.
- `floor` is static: send it with the grid (like `g`) and keep it on the guest across snapshots.
- Integration: `floor` travels with the grid as `fl` (base-36 string, null without tiles); `unpackSnap(p, prevGrid, prevCfg, prevFloor)` keeps it on lean snapshots and `main.js` resets `lastFloor` in `toMenu`. The `lobby` message carries `rules: {mode, tiles, chaos}` (guest runs it through `sanitize`). Settings `mode`, `tiles`, `chaos` live in the Match panel.
- Participants vs players: `humansOf(s)` / `g.n` is the number of humans; survival adds 12 enemy slots, so never use `players.length` for scores, names, recaps or rematch. `hudEntries` filters dormant slots, `teamsOf` is null in survival. `director` stat arrays are 16 long and ignore owner -1 bombs.
- Non-classic modes show their banner through the `intro` freeze; survival ends the match after one round ("Survived N waves"). Bots think staggered by player id. `look.js` holds `FLOORC`, `EVENT_INFO`, `MODE_INFO`, `spikePhase`, `eventText`, `modeText`, `foeLook` and `view.still`. 3D extras are pooled/instanced and hidden unless the state has them. `renderfps.js` still ignores floor and mode visuals.

## Sound (`music.js`, `sound.js`, `audio.js`)
- All procedural WebAudio, no assets. `music.js` is pure (seeded plans and bars, 8-bar loops, styles Arcade/Epic/Chill/Synthwave + quiet menu variant), `sound.js` is the pure state-diff observer (reuses `fx.js` events, adds explosions, extras, stingers), voice limiter (16, priority + min gap per name) and `createSound` with injected `makeEngine`, settings, speech and clocks; `audio.js` is the engine (`createEngine(ctx)`, 47 recipes, also runs on an `OfflineAudioContext` for measurement; compressor then tanh soft clip).
- Settings `sfx`, `music`, `volume`, `voice` (flag `sound: true`, `#soundList`); mute is localStorage `mute`, toggled by N or `#muteBtn` (always visible during play). Voice speaks `g.call` only when Announcer is on and is off by default. No gamepad mute (every pad button drops a bomb).
- A new sound needs a `SFX_INFO` entry (priority, gap) and a `RECIPES` entry (a test enforces they match). `main.js` calls `snd.feed(game)` per frame, `setScene` in `startMatch`/`toMenu`, `setPaused`/`setHidden`.
- Frugality: the context is created on the first gesture and only if something can sound; suspended when paused, muted, hidden or silent in the menu; music scheduler is one 400 ms timer while music plays; mobile drops delay line, detune and layers. Auto music: theme picks the style, survival/potato/hill/boss adjust tempo and minimum intensity, level 2 (sudden death) adds 12% tempo.

## Bomber Shooter (experiment, first-person mode)
- A fourth graphics mode ("First-person" in the Graphics toggle): a software raycaster over the same game state, so it works in solo, local, story, host and guest. Files: `raycast.js` (pure DDA/projection math, tested against a brute-force marcher), `fpsinput.js` (facing + input transform), `fpstex.js` (procedural paletted textures and sprites), `renderfps.js` (renderer + status-bar HUD + minimap), tests `raycast.test.mjs`, `fpsinput.test.mjs`. To remove the experiment: delete these files and revert the small hunks in `main.js` (import, `GFX` allow-list, `is3()`/`fpsOn()`, input transform, `fps.reset()`, draw dispatch), `index.html` (4th `#gfx` button, `<canvas id="cf">`, help lines) and `sw.js` (FILES).
- Controls (first human only; in local games P2 keeps classic controls): left/right turn 90 degrees (repeat after 20 ticks then every 12), up/down walk along the facing axis, strafe on Comma/Period or gamepad LB/RB, M toggles the minimap (persisted as `fpsmap`). The sim input stays axis-aligned `{dx, dy, bomb}`; `fps.map` must be called once per sim step.
- Perf: internal height 200 (150 on mobile, drawn at ~30 fps), no per-frame allocation in the 3D pass. In V8, writing doubles into object fields, passing doubles to non-inlined hot functions or using a literal `Infinity` allocates per call: keep ray state in typed arrays. `rf.ms` is an EMA of draw time for debugging.
- Floor tiles (ice, conveyors, teleporters, spikes) and the hill zone are 32x32 overlay textures from `fpstex.js` `floorOverlays`, sampled per pixel in `floorCeil` only when `s.floor` or `s.hill` exists, so the classic path is untouched. Conveyor scroll is `tick & 15`, frozen by reduce motion. Chaos telegraphs are ring and column markers (`beacon`), quake targets tint the wall columns. Hill is a floor tint with points in the scoreboard, potato an aura plus a fuse bar, survival enemies use `foeLook()` (red ring, no digit); `modeText` and `eventText` show as HUD lines at the top left.

## Special bombs, glove/punch, abilities (opt-in)
- `newGame` opts `bombs: true` and `abilities: true | [ability keys by player]` set cfg flags and extra fields only when on. Never add a field, `roll()` or `rand()` to the classic path: `determinism.test.mjs` holds 20 golden hashes captured before the feature and must never be regenerated.
- Items 8..12 (glove, punch, cluster, mine, frost); `b.ty` 1 cluster, 2 mine, 3 ice, 4 mini-blast. Player fields `sp/spn` (held type and count), `fz` (freeze), `gl/pn`; with abilities `ab/cd/inv/dash`; bombs `ty`, `fx/fy/fa` (throw arc). Bomb key priority: glove (standing on a bomb), punch (bomb ahead), place, remote detonate; `canLift` is shared with the guest.
- Cooldown, vanish, freeze and dash timers run inside `movePlayer` so guest prediction stays exact; `useAbility(s, p, host)` only touches `p` on the guest, effects on bricks, bombs or other players are host-only (swap, sweep, crack, overload, rise, throw, punch, mine triggers, freeze application). `ABILITIES` holds `[key, name, cooldown, description]` (the help list is generated from it); story fighters have `ROSTER[].ability`, colour slots get Dash, Vanish, Overload, Blink; story only passes the options when the settings are on.
- Mines are non-solid, never use bomb slots and are hidden unless `mineSeen` (owner and team; the snapshot still carries them: same class as the host-can-cheat limit). Ice flames freeze instead of killing (shield resists, a normal blast still kills a frozen player).
- Wire: input code +18 = ability key (`createInbox` accepts < 36), ice flames pack as `[x, y, t, 1]`. Keys: kb1 E/Left Shift, kb2 Right Shift/Numpad0/0, pad X (button 2) only when `pads.act` is set (otherwise any button bombs), touch `#actBtn`. First person uses the last walked direction.
- Known pre-existing stalls (not caused by this feature): a teleporter pad can land a bot in a soft-wall pocket; bot-only survival may never end. Bot ability use lives in `ai.js` (`escapeAct`, mine planting).

## Replays, daily challenge, share cards (all client-side)
- `replay.js` (pure): `rec.step(s, inputs)` records every player's input (bots included) before `step`; binary format "KB" v1 (varint runs `(len-1)*36 + code`, JSON head with per-round seed/opts/end-state hash `h`), deflate + base64url text; `decode`/`unpack` never throw (`{match}` or `{error: "version"|"corrupt"}`, strict allow-lists and hard caps). Playback with keyframes every 300 ticks for seeking; `settle` is the shared round-end scoring used by live matches and replays. **Bump `SIM_VERSION` whenever `sim.js` behaviour changes**, and never innerHTML a replay field.
- `main.js` `mode = "replay"` re-runs `tick()` with recorded inputs, so all four renderers, sound and banners work unchanged (recap, haptics and slow-mo are off). The last 10 finished matches live in localStorage `replays` (450 KB cap). Links are `/#r=<text>` capped at 8000 characters (trimmed to the last round, else a `.kaboom` file); there is no `?replay=<id>` because nothing is stored server-side.
- `daily.js` + `dailyui.js`: UTC date key, 14 curated rules rotated by day, fixed fighter/colour/ability per rule, one score formula (`score()`, tested) per mode family, streak and best in localStorage `daily`. `sharecard.js`: pure 1200x630 `cardLayout` plus canvas glue (`navigator.share({files})` or PNG download).

## Bots (`ai.js`)
- `dangerMap` gives the time before impact per tile (chain reactions included); escapes are timed (`ticksPerTile`, `MARGIN`) and a bomb is only placed if a strict escape exists. Bots anticipate sudden death (`doomed` in `sim.js`).
- Do not reintroduce "bang-bang" lane re-alignment in the steering: corner sliding in `move` (`sim.js`) handles it.

## Online
- The relay (`RoomChannel`) enforces roles (host = first subscriber), message-type allow-lists, size and rate limits, and connection caps: any new network message must go through those allow-lists. The UI must never put network-received data into `innerHTML` without coercing or escaping it.
- Every relay guard logs one line `kaboom refus=throttle|probe regle=... ip=... chemin=/cable` (`Connection.refuse`), a format parsed by an external log monitor. New refusals go through it; do not change the format casually.
- Known limits: the host can cheat and a host in a background tab freezes the game; a host drop ends the match.

### Quick play, spectators, emotes (relay v2)
- `RoomRegistry` (plain Ruby, tested by `ruby -Itest test/room_registry_test.rb`; `bundle exec ruby -Itest test/connection_limits_test.rb`) holds rooms, caps and the public list; `RoomChannel::REGISTRY` replaced the old `ROOMS`/`LOCK`. Subscription params `{code, cid, tok, host, auto}`: `tok` (8-32 chars `[a-z0-9]`, per page load, never broadcast) proves ownership of a roster slot on reconnect; `auto` (guests) falls back to spectating when the room is full or started. The server assigns the role and sends `{t:"role", r:"p"|"s", host}` to that subscription only; `{t:"spec", n}` is server-only (host re-pushes lobby and a full-grid snapshot).
- Allowed types: host `lobby snap start end full pong emote`; guest `join in ping emote`; spectator `ping emote`. Rates per second host 90, guest 40, spectator 6; size caps join 512, in 2048, ping/emote/spectator 256 bytes, host 32 KB. Caps: 4 players, 6 spectators per room, 200 rooms, 3 subscriptions per connection, 8 per IP and 300 total connections. 20 misses (unknown room, host probes) per IP per minute -> `join/ip`. Rooms idle 2 h are swept lazily; no timers.
- Public list: `ListingChannel` `list` action (on demand only: Quick play, Public rooms, Refresh), up to 20 rows from a whitelisted summary of the host `lobby` message (`pub`, `sp` flags); private rooms are never listed; public status expires after 30 min. The client re-validates every row (`cleanRooms`) and renders with `textContent`.
- Emotes: `{t:"emote", e:0..7}`, server accepts only a real Integer 0-7 and rebuilds the message; 2 s client cooldown, 1.5 s relay. Keys 1-8 (plus a button/wheel online), `emote.js`, setting "Emotes" (hides others' only). Spectators run as `mode "guest"` with `spec = true` and `me = -1`, are not recorded and take no lobby slot or rematch vote.
- New `regle=` values (log format unchanged): `sub/conn`, `join/ip`, `join/tok`, `room/total`, `emote/arg`, `emote/rate`, `list/rate`. Per-IP limits use `request.remote_ip`: the reverse proxy must forward the real client IP.

### Netcode (`netcode.js`, tests in `netcode.test.mjs` with a host+guest harness simulating latency, jitter and loss)
- The guest sends its inputs per tick, at most 30 msg/s (`{t:"in", n, d:[codes]}`, nothing when idle). The host replays them through `createInbox` (one input per sim tick; a missing tick repeats the held direction, idle after 12 ticks; `ack` = guest ticks consumed, returned in every snapshot).
- The guest predicts its own player with `movePlayer`/`placeBomb` from `sim.js`: on each snapshot it restarts from the authoritative state and replays unacknowledged inputs; a gap under 24 px is smoothed (decay), larger ones teleport. Other players and bombs are rendered ~100 ms in the past, interpolated between snapshots (clock = host tick, offset = min of arrivals); renderers do no smoothing of their own. A locally placed bomb is a "ghost" until confirmed.
- Compact snapshots (`packSnap`): grid as a string and `cfg` only when changed or every 60 snaps, flames as arrays. RTT: `ping`/`pong` every second (allow-listed in `RoomChannel`), shown at the bottom (`#ping`). Debug: `?lag=120&jitter=40` delays every message in each direction (order preserved).
- Sliding (kicked) bombs are drawn from `sc` (`bombPos` in `look.js`); `createGuestNet.frame` extrapolates `sc` between snapshots.
- Not predicted by the guest: item pickups, kicks/sliding bombs, curse and shield timers (the snapshot corrects them within the 24 px smoothing).
- Limits: item pickups are not predicted (small correction when a guest grabs one); the local player never sees others in the present (100 ms visual delay, collisions decided by the host); a guest with no input for 12 ticks is considered idle.

### Lobby and online UX (`lobby.js`, pure, + `lobby.test.mjs`)
- No dedicated message types. `join` carries `name` (guest); `lobby` = `{slots, names}`. Names go through `cleanName` (<= 12 chars, no control characters) on send AND receive and are shown via `textContent`/canvas (`esc` for the 3D HUD); labels ("Bot N", default colour names) are recomputed everywhere by `displayNames`.
- Invite link: `/?room=ABCD` joins directly (URL cleaned); the QR comes from `vendor/qrcode.mjs` (qrcode-generator, MIT, licence next to it).
- Rematch: only the host chooses (`rematch` in `game`, relayed to guests as `r` in the snapshot); scores reset.
- Guest reconnect (30 s, overlay `#reconn`): same `cid`. ActionCable resubscribes by itself; if the resubscription is rejected (old subscription still registered server-side, duplicate `cid`), `net.js` `retry()` recreates it every second. While away the host drops the inbox (a bot plays) but keeps the slot reserved (`release`/`admit`) for the duration of the match; a `join` from the same `cid` gets it back (new inbox). Outside a match, leaving frees the slot.

## Deployment
- A `Dockerfile` is provided (read-only rootfs, single Puma process, no volume); `deploy.sh` is the author's script for one server behind a shared reverse proxy (it builds the image on the host).
- Production expects `SECRET_KEY_BASE`; allowed hosts and WebSocket origins are set in `config/environments/production.rb`.
